# audiOS 0.1 Design

audiOS is a 64-bit, command-line-first operating system for digital audio work. Milestone 0.1 boots on x86-64 (QEMU and real PCs, including BIOS-era AMD FX machines), presents a musical-computer shell, and installs the audio subsystem as a first-class kernel service — without implementing a DAW.

## Approach

Limine loads a freestanding ELF64 kernel into long mode and provides a framebuffer plus a physical memory map. The kernel owns interrupts (PIC + IDT), a PIT clock, PS/2 keyboard input, COM1 serial (for bring-up and automated tests), and a framebuffer console. Audio is a kernel object with a published configuration (96 kHz, 24-bit, 2 channels) and reserved stream/graph interfaces; the engine itself is not started in 0.1.

Rejected alternatives: a custom 16-bit BIOS chain (more fragile, slower to reach 64-bit), GRUB/Multiboot2 (heavier ISO story), and VGA text mode only (cannot render the identity banner cleanly and fights Limine’s default framebuffer).

## Components

| Unit | Responsibility |
| --- | --- |
| Boot (Limine requests) | Handshake, framebuffer, memory map |
| TTY | Dark-console output to framebuffer and serial |
| Interrupts | IDT, PIC remap, exception halt |
| PIT | 1000 Hz system timer and uptime |
| Keyboard | PS/2 scancode set 1 → ASCII |
| CPU / mem | CPUID and physical map summaries |
| Audio | Subsystem status + future-facing stubs |
| Shell | `help` `clear` `version` `cpu` `mem` `audio` `reboot` |

## Shell identity

```
audiOS 0.1
96 kHz • 24-bit • 2 channels
audiOS>
```

The prompt is not a Unix shell: no paths, no `$`, no user accounts. Unknown input is rejected with a short hint to `help`.

## Out of scope (0.1)

GUI, networking, filesystems, user accounts, DSP, synths, effects, Ambisonics, HRTF, and a package ecosystem.

## Verification

`make test` builds the ISO and drives the shell over QEMU serial: banner, every command, and `reboot` causing QEMU to exit (`-no-reboot`).
